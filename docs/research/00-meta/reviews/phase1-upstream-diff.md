## Missed items

1. **The WSL2 3090 A/B of b4b97ec (P1, most important).** TyroneNel's comment on PR #345 (2026-10-20) reports 3 boots per arm on a headless 250 W 3090 under Docker Desktop/WSL2 (image `sha-95ac251`, `GPU_UTIL=0.89` because fp8 spilled at 0.93). Results: decode +21.3 % at ~66k and +22.1 % at ~93k; step time -18.5 % / -17.4 %; tokens per step equal within 1 %; GSM8K, all 1,319 items, 0.9507 vs 0.9522; pool -1.5 %; the fp8 arm ran piecewise graphs only (upstream-reported). That setup matches this project's GPU box. The doc quotes only the native +9 % and +12-14 %. Added under "Reviewer additions".
2. **Boot-refusal edge case**, same thread: the int8 pool is ~1.9 % smaller, so vLLM 0.31.0 refuses to boot at `MAX_LEN` 150000 when `GPU_UTIL` or `KV_MEM` leave the fp8 pool within ~2 % of it. This matters for any EAGLE-4 arm that changes `GPU_UTIL`. Added.
3. **Open questions 1 and 4 are answerable from the references.** `deepinfer-ref/.../gpu-results/ENVIRONMENT.md:24-26`: the box serves the stock image built from 2cf50a0, so its launchers are baked in and b4b97ec is already live there. Only `bench/` is bind-mounted, from `research/deepinfer`, which contains 373a695. The gpu-results commits (3ceb21f, 21:35) postdate merge 88549e7 (21:32), so the DeepInfer 3090 figures most likely used `perf_counter` (**estimated** from commit order, not checked run by run). Added.
4. **The box defaults switch the new default off.** `ENVIRONMENT.md:27`: the box `.env` sets `CTX=fast` and `VISION=1`. The mtp PTH_FA default needs `CTX=long` and `VISION` not 1 (`resolve_config.sh:105-107`). An arm that inherits the box `.env` runs fp8 + FlashInfer even after the fast-forward. This sharpens §6.1. Added.
5. **No KV-sharing gotcha landed.** mhenrichsen's #96 closing comment promised a gotcha for this result, but `git grep -i 'kv.sharing\|group:2' upstream/main -- docs README.md` finds nothing. The negative result exists only in the closed PR. Added.

# Decisions and assumptions

| # | Decision | Why |
|---|---|---|
| D1 | **No GPU on the research box.** Phases 2 and 4 run everything CPU-feasible here and package every GPU measurement (harness, configs, patches, ledger rows, a GPU agent prompt) for the RTX 3090 box, as the DeepInfer expedition did. Nothing in this report is labelled *measured* unless it has raw evidence from a real run. | `nvidia-smi` missing, no `/dev/nvidia*`, `torch.cuda.is_available() == False`. The prior expedition documents the same split (`deepinfer-ref/.../gpu-agent-prompt.md`). |
| D2 | **Baseline = the prior expedition's measured 3090 runs**, cited by commit (`origin/research/deepinfer` `86ce6ed`, `gpu-results/baseline.md` and siblings). They are labelled *measured (prior, GPU box)*. The phase-2 "independent re-run" becomes an independent re-derivation of those numbers from their raw files, plus a CPU self-check of the new harness; a real re-run is a GPU-queue item. | Only real 3090 numbers available; the stock image they used (`sha-2cf50a0`) is what our branch would serve. |
| D3 | **DeepInfer research is context, not a source of ideas.** Agents may use it as a map of our own code and as measured facts about our stack, and should cross-reference overlapping items, but techniques from DeepInfer/DeepSpec are out of scope. | Scope rule: outside ideas come from EAGLE-4 only. |
| D4 | Branch `research/eagle4-expedition` is cut from `origin/main` (`95ac251`) as instructed, without merging `upstream/main` (5 commits ahead, `63f7581`). Harness scripts live under `docs/research/04-benchmarks/harness/` and bind-mount into the stock image, so the branch needs no serving-code changes. | Rule: only report, scripts and results on the research branch. |
| D5 | Agent definitions are written to `.claude/agents/` but not committed. Confirmed: this session did not pick them up (spawn by type failed, "Agent type not found"). So, agents spawn as `general-purpose` with the `model` and `effort` overrides on the Agent call; the agent log records the actual type used. | Definitions are tooling, not report content. New agent files may need a session restart to load. |
| D6 | Serena is pinned to this project in this session (no `activate_project` tool exposed). Agents use Serena for our code and Grep/Read for EAGLE-4, upstream and vLLM. No agent switches Serena's active project, because parallel agents share the server. | Avoid cross-agent races on the shared MCP server. |
| D7 | Context7 is not available in this session. Library API claims are checked against the pinned source trees (`~/vllm`, installed torch) instead. | Tool not connected. |
| D8 | Commits omit the `Co-Authored-By` trailer. | User's global CLAUDE.md: the user is the sole author of commits. |
| D9 | The orchestrator cannot set its own reasoning effort; subagents get `effort: high` (fact checker: `medium`) through frontmatter or the Agent call. | Effort ceiling rule. |
| D10 | The harness pins `PTH_FA` explicitly in every arm and records it per run. | Upstream `b4b97ec` (#345) flips its default for `SPEC=mtp CTX=long` on sm86; our branch's launchers (`95ac251`) and the stock image (`2cf50a0`) disagree (upstream-diff lane). |
| D11 | **Needs the human:** whether shipping our own low-rank candidate head (or anything derived from the EAGLE-4 draft) in HyperQwen falls under the EAGLE-4 licence's "Competing Offering" clause. The report treats licence-gated items as blocked pending that decision and never as quick wins. | Legal judgement, not ours to make (training-recipe lane). |
| D12 | A draft/verify timing patch is wanted, but as a phase-4 experiment in a separately tagged variant image, never in the stock image or `patches/series`. | Draft vs verify time is a required P1 metric and no telemetry exists (bench-engineer). Keeps baselines re-runnable on the stock image. |
| D13 | Questions only the GPU box can answer (are launchers baked into the image or bind-mounted, is pthfa installed, which LABD corpus is frozen, does `G:\dev\hq-results\deepinfer-20261020` still hold the raw jsonl/csv) go into the GPU agent prompt as step-0 checks, not to the user. | They are facts on the box, not decisions. |

Two cheap moves. Benefits

Problem

"Is step X done?" for the model-preparation pipeline is authored three times: the scripts themselves (which know the real tensor names), docker/prepare.sh's state() — a Python heredoc living inside shell, pattern-matching weight_packed names out of the index — and verify.sh's model checks. Both CI tests that exercise this (test_model_verification.py, and since #195/#203 test_prepare_state.py) do so by string-splitting the heredoc out of shell source on a literal marker. So the done-ness protocol of a ~20 GB artifact pipeline is maintained in a language the writers don't run, and tested through a parser of a parser. Rename a tensor and you edit the script, the heredoc, and verify.sh — miss one and prepare silently re-runs or skips a step.

Deep-dive addendum (verified): the string-split is verbatim at test_model_verification.py:18-19 (splits on $PY - "$MODEL" <<'EOF'), and the same file's second test (:59-91) already proves the healthy pattern — it replays files (entrypoint.sh, select_model.sh) instead of parsing shell. verify.sh's model block is a genuinely skeptical third implementation (group_of at :187-197 re-derives vLLM's find_matched_target semantics; symmetry/zero-point rules at :145-224 — was cited :168-179 and :126-179, which at 2522ef9 already stopped short of the checks) — and it is torch-free (imports only json/os/sys at :133, re at :176; heredoc marker at :132), so it extracts cleanly into scripts/verify_model.py: verify.sh calls it, the test runs the file, the heredoc and the string-split both die. Also load-bearing: tokenizer.json in the state check (:31-33) — without it the dir looks servable until startup. Since the review: state() also grew intact() (:41-53, #203) — torn shard → download — a fourth done-ness implementation, while #195's atomic_publish.py made the writers' index the declared commit point. The publish contract is written down; the predicates still live in shell.

Solution

Each prepare script grows a --status probe (script.py DIR --status → exit 0/1 + a one-line reason). The tensor names stay in the file that writes them; prepare.sh's state() becomes a loop over the probes and keeps only orchestration (flock, dispatch, the harden/translate passes). Keep verify.sh's checks as a deliberately independent second implementation — its skepticism (packed-geometry and zero-point cross-checks) is a feature; share names and predicates, not the verification semantics.

Benefits

  • Locality: the done-predicate for a step lives next to the code that performs the step — the heredoc stops being a third author.
  • Leverage: adding a pipeline step (third-party checkpoints are on the roadmap) is "write script with --status," not a three-layer edit across shell, Python and CI.
  • Tests: probes are cheap subprocess calls against tmp-dir fixtures in the existing test style — no shell-surgery parsing in CI.

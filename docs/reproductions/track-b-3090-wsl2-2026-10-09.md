## Run 1. T1 on E (B1, Q2)

**Verdict: both speed bars missed. The copy bar passed. Quality: one bar missed, by 1.5 GSM8K points (C against A). Needles: no verdict, because the instrument is broken.**

**Boots.** Each arm was started as `CTX=huge SPEC=dflash2 PREFIX_CACHE=1`: A (knobs off), B (`KVARN_FP16_DEQUANT=1`), C (`KVARN_FP16_DEQUANT=1 KVARN_SHARED_VERIFY=1`). There were 3 repeats, with the arm order rotated: ABC, BCA, CAB. Each arm got one fresh boot per repeat, 9 boots in all.
- argv, the same for all three arms (the knobs are env): `serve /app/models/Qwen3.8-27B-W4A16-AutoRound-fast … --max-model-len 245760 --max-num-seqs 2 --kv-cache-dtype kvarn_k4v2_g128 --block-size 128 --mamba-ssm-cache-dtype float16 --async-scheduling --max-num-batched-tokens 2048 --speculative-config {"method":"dflash",…,"num_speculative_tokens":7,…} --compilation-config {"max_cudagraph_capture_size":16,…} --prefix-cache-retention-interval 13056 … --kv-cache-memory=5261334938`.
- Every boot: pool **268,169 tokens**, `Initial free memory 22.76 GiB`, 23,368–23,372 MiB in use after boot and 23,684–23,688 MiB after the cells.
- Shared GPU memory through the speed cells: 92 → 106 MiB. That is within 14 MiB of the baseline, so the working set stayed on the card.
- Boot time: about 420 s on a fresh compile cache (B, C, and A's first boot), and 90 s on A's warm cache.
- 0 engine errors and 0 `nvlddmkm` events on all 9 boots.

**Depth calibration.** §0.3's `--ctx` values gave fewer tokens here than its 1.13 ratio predicts. A calibration boot of A at 80000 / 132000 / 213000 read prompts of 85,689 / 131,780 / 202,118. A tokenizer count of `corpus[:ctx*3.6]` (the slice `labd_bench.py` takes) gave the values used, as §0.3 says to do ("read `prompt=` … and adjust"): **85000 / 153000 / 254500**. The prompts landed at 90,009 / 149,231 / 240,102 tokens. The calibration boot's rows are kept with the results and are not in the tables.

- **The GSM8K miss sits inside this battery's noise.** In A6 (same image, `CTX=fast`), the same battery at n=50 read 0.96 on two trees and 0.98 on two others, with no client change between the middle two (`git diff` of `quality_battery.py` empty). It sends 32 GSM8K requests at once. One run per arm does not separate 1.5 points from that noise. It was not repeated here: §0.3 asks for one battery per arm.
- **`needle_test.py` gives no needle verdict on this model.** It sends `max_tokens: 32` and does not turn thinking off (`bench/needle_test.py:58-62`). The model spends the 32 tokens reasoning and `content` comes back empty, on both arms and at both depths, and on `CTX=fast` in A6 too. `needle_reuse.py`, which pins thinking off, found all three needles at 30k in A6.
- The battery's prompt_logprobs pass moved shared GPU memory from 92 to 348 MiB on both quality boots, so about 256 MiB spilled to host RAM. That was after the speed cells, on separate boots. The later checks (residue, collapse, soak) ran in that state.
- 0 engine errors and 0 `nvlddmkm` events on both quality boots.

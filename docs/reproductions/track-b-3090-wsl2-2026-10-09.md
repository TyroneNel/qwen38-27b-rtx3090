## Run 5. T2 boot check (B5, Q6), run on 2026-10-10

**Verdict: it refuses at boot, as expected, but not with the refusal the plan predicted.** The first refusal is the attention backend, not GDN.

- Env file: `base.env` + `SPEC=mtp CTX=long` + `EXTRA_ARGS=--speculative-config {"method":"mtp","num_speculative_tokens":3,"draft_sample_method":"probabilistic","enable_adaptive_verification":true}`. The launcher's own `--speculative-config` comes first in the argv. The one in `EXTRA_ARGS` comes later and wins. Also in the argv: `--max-model-len 150000 --kv-cache-dtype fp8`.
- The log says `Using V2 Model Runner` (`gpu_worker.py:441`). Then: `Using TRITON_ATTN attention backend out of potential backends: ['TRITON_ATTN']`. FlashInfer, the backend `CTX=long` normally gets, is not in the list.
- It dies 100 s after start, while it builds the first attention layer (`triton_attn.py:677`):

  `ValueError: FP8 KV cache is not supported by the Triton attention backend on NVIDIA GeForce RTX 3090 (compute capability 8.6); native FP8 (fp8e4nv) requires SM89+. Re-run with --kv-cache-dtype bfloat16.`
- No GDN/SSM `ValueError` shows, because the boot does not get that far. [INFERENCE] With adaptive verification on, the backend list is cut to backends that allow the query-length mismatch. On sm86 that leaves Triton, and Triton refuses fp8 KV.
- 0 `nvlddmkm` events.
- **Follow-up boot, `--kv-cache-dtype bfloat16`** (the owner asked for it; `MAX_LEN=65536`, so a bf16 pool can hold it). The backend list is now `['FLASH_ATTN', 'TRITON_ATTN', 'FLEX_ATTENTION']`, and FLASH_ATTN is picked. The boot gets past model load, then fails 240 s in, at `maybe_create_adaptive_verification_manager`, with the refusal the plan predicted:

  `ValueError: Adaptive verification trims verification requests on device, which the GDNAttentionBackend attention backend does not support. Pass enable_adaptive_verification=false in the speculative config, or use a backend that does.`

  So on sm86 with this model, adaptive verification meets two refusals in turn: first the backend (with fp8 KV), then GDN (with any KV dtype).

## Run 4. T4: DFlash2 with fp8 KV on the FA2 plugin (B3), run on 2026-10-10

**Verdict: fp8 + FA2 matches int8 + Triton on quality and stability. It decodes faster at 90k, and its cold prefill at 60k is about 42% shorter. The 149k boot with `EMBED_UVA=1` did not boot on WSL2.**

Arms, each with its own compile cache, `SPEC=dflash2 CTX=long` (k=7, `MAX_SEQS=2`, `PREFIX_CACHE=1`):

- **fp8 + FA2**: the same, plus `EXTRA_ARGS=--attention-backend FLASH_ATTN --kv-cache-dtype fp8 --speculative-config {…,"attention_backend":"FLASH_ATTN"}`.

- The 90k cell runs after the 60k cell on the same boot. The two prompts share their first ~60k tokens, so the 90k TTFT on both arms includes some prefix-cache reuse and is not a cold-prefill number. The 60k cell is cold on both arms.

## Why this took 13 hours

The session ran about 13.5 h (07:30–21:05 UTC). Wall time by phase, from the boot and cell timestamps in each `summary.txt`:

| phase | wall | where the time went |
|---|---|---|
| setup | 0.6 h | model download and prepare 19 min, quality data, corpora. Both images came from CI's cache in about 1 min each |
| A6 | 2.9 h | 4 passes × 36–39 min, plus 22 min of `prefix_alternation.py` reruns. Each pass: `run_benchmarks.sh` 9–10 min, `conc_ladder.py` 8 min, `prefix_alternation.py` 5.5 min, the other 15 scripts 13 min |
| A7 | 0.4 h | 18 GiB download 14 min, two root copies 8 min, two prepares 3 min, a boot and `verify` 7 min |
| D2 | 0.2 h | two boots |
| Run 1 | 5.4 h | 9 speed boots 2.5 h, a calibration boot 18 min, two quality boots 2.6 h |
| Run 2 | 4.1 h | 7 boots of 31–39 min each |

**The causes, largest first:**
1. **The handover's own soaks and sweeps.** Fixed-duration checks are more than half of all GPU time:
   - Run 1: 2 × 30-min soaks, 2 × 12-min residue sweeps (128 residues, each sent twice), 2 × 13-min collapse checks (30 trials).
   - Run 2: 4 × 30-min soaks and 4 × 23-min residue sweeps.
   - Runs 3 and 4 add two **240-min** soaks, 8 of the remaining ~12 h.
2. **Cold compile on every boot that sets a KVarN knob.** The prompt asks for a fresh `/cache` volume for each such boot, so each pays torch.compile, CUDA-graph capture and Triton autotune again: 390–510 s per boot, against 90 s on a warm cache. 15 of the 20 Track B boots were fresh, and the calibration boot was also cold. That is about 1.5 h of compiling. The knob is in the compile key, so a per-arm volume reused across that arm's repeats would compile correctly and save most of it. It would also fix the Triton autotune pick within an arm, which the T1 history says varies by boot. That is a trade-off for the owner.
3. **Prefill at depth, paid again on every boot.** One LABD cell on E prefills 90k in 98 s, 149k in 120 s and 240k in 235 s. The second task of each cell reuses the prefix (TTFT 5–9 s). That is about 7.5 min of prefill per run-1 speed boot, and about 1.1 h across the 9 boots. Prefix-cache reuse cannot carry across boots, and one fresh boot per arm per repeat is the handover's design.
4. **Slow decode at depth.** 1,024 tokens per cell at 9–26 tok/s takes 40–110 s per depth cell, and the knobs-off arm is the slowest.
5. **Boots in run 2's design.** Each arm boots twice, once without and once with prefix caching: 8 boots for 4 arms.
6. **Checks that returned nothing.** `needle_test.py` at 150k and 240k took 22 min in run 1 and can only print `MISSED` on this model (thinking is not turned off). The 18 min calibration boot was needed because §0.3's `--ctx` values undershoot on this corpus.
7. **Choices I made that added time:**
   - A6 ran 12 scripts beyond the 6 the prompt names, about 52 min over the four passes.
   - The `prefix_alternation.py` reruns (22 min) were needed because the read-only mount refused its default output path.
   - Run 3 as prepared (not run) adds a k=3 quality battery, because its PPL bar needs a k=3 baseline.

WSL2 itself is not the main cause. Shared GPU memory stayed within 30 MiB of its baseline in every speed cell and in all of run 2. Only the quality battery's prompt_logprobs pass spilled. Restarts took about 25 s. Image builds took about 1 min.

**To cut the remaining ~12 h to about 3 h:**
- Shorten the two 240-min soaks to 30 min, as in runs 1 and 2. That saves 7 h, but loses the long-soak evidence that #34 and #121 ask for.
- Use one compile-cache volume per arm, not per boot.
- Drop `needle_test.py` until it turns thinking off.
- Run run 5 first: it takes 10 minutes.
